# 制作看板（Production Board）

把一份口播逐字稿变成一个能预演、能直接动手改的视频制作看板。成品是一个单独的 HTML 文件：

- **剪辑台**：上面是预览画布（手绘分镜风格）+ 镜头信息，下面是像剪辑软件一样的时间线。
- **时间线**：V1 口播 / V2 录屏 / V3 B-roll / V4 叠加贴四条画面轨，A1 口播 VO / A2 音效 / A3 音乐三条音频轨。clip 可以拖动、拖两端改时长，有联动、波纹、磁吸、撤销。音乐、音效、口播录音直接从电脑拖进音频轨，可以裁剪、淡入淡出、调音量，按空格整片连声音带画面预演。可以导出 FCP XML，在 Premiere、达芬奇、Final Cut 里打开。
- **预览画布**：每个 clip 上的元素都画在画布上，可以直接拖动、改大小、改文字、加删元素。
- **素材画布**：一张可以无限平移缩放的节点画布，左边是「库」：镜头库（全部镜头）和风格库。默认只放好要用户自己录屏、实拍、找素材的镜头框，其他镜头从库里拖进来。拍完把视频或图片拖进框就算到位，剪辑台预览会直接换成真素材。风格、动效参考、便签放在画布上，从节点右侧的圆点拉线连到镜头，表示“这个镜头照这个来”；风格节点上的「生成动效任务」会把风格说明和连上的镜头整理成一份任务，复制给做动效的 Agent。连线也会显示在剪辑台的镜头信息里，并随「复制修改给 AI」带回来写进镜头的 `ref`。
- **风格资产库**：内置 66 种用 Opus 5.5 纯代码做出来的影片风格，来自 GitHub [lemomo-ai/lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar)（MIT，每种风格有一份 STYLE.md 和样片截图，截图已内嵌在模板里，离线也能显示），加上用户自己的四个动效技能（黑灰纸面寓言、黑底霓虹数据讲解、桌面分身、档案编辑感剪辑），以及 `BOARD.styles` 里本片专用的风格。可以按分类筛选、搜索，一键加到素材画布。四个自己的技能风格默认是按描述画的示意图，用户把成片截图拖到风格卡片上就换成真实封面（存在浏览器里）。
- 另有故事板、录屏与素材清单、B-roll 清单、版式与转场、准备与核实、评论与改动。

在 Claude、WorkBuddy、豆包等能生成并打开 HTML 的环境里都能用。

整体流程：收到口播稿 → 确认信息 → 拆镜头 → 逐镜填写 → 生成 HTML 交付 → 按评论和改动回改。

## 0. 演示图一律用手绘分镜风格

这个技能里出的所有演示图——看板里每一镜的画面预览、故事板、版式示例，以及单独给用户看的分镜图——都是**手绘分镜风格**：米白纸面、黑色铅笔/墨线轮廓、灰色斜线排线表示明暗、手写字体、红笔圈重点、蓝笔标运镜。模板引擎已经把所有画面元素渲染成这种风格（墨线抖动、双线铅笔描边、排线阴影），不需要也不要再去模仿成片的配色。

- 成片的真实风格（黑灰纸面、深色科技等）写在 `style` 和 B-roll 清单里，给做动效的人看；预览画面只负责讲清楚“画面里有什么、在哪、怎么动”。
- 镜头写了 `ref` 的，做这一镜的动效或拍摄时以 `ref` 为准：它比全片的 `style` 更具体。之后有 Agent 按看板做动效时，先读每个镜头的 `ref`，再读 `style`。
- 运镜、动作要画出来：推拉摇用 `cam`，人物或元素的运动方向用 `mv`，导演批注用 `note`。
- 如果需要在看板之外单独出分镜图（比如用户要一张图发给别人），同样画成手绘分镜：纸面、墨线、排线、手写标注，不要出写实效果图或成片色板。

## 1. 先确认，再动手

读完口播稿，把还不知道的一次问完：一条消息，最多 6 个问题，每个问题附推荐默认值，用户回“默认”就按默认做。用户已经说过的、对话或记忆里已有的（比如惯用字体、音效规则、B-roll 风格），不要再问。

1. **画幅**：横屏 16:9、横屏 4:3、竖屏 9:16、3:4 还是 1:1？分辨率、帧率？（默认 16:9，1920×1080，30fps）
2. **A-roll**：有没有出镜口播？人物站在哪一侧？（默认有，站左三分线，右侧留给叠加贴）
3. **B-roll**：要不要动效 B-roll？什么风格？有没有已有风格、风格 Skill 或往期视频可参考？要不要透明叠加贴？（默认「黑灰纸面」预设，带叠加贴）
4. **素材**：哪些地方要录屏（电脑还是手机、哪个软件）、哪些要实拍、哪些用网络素材或已有素材？素材放在哪？（默认按口播内容推断，列进清单让用户确认）
5. **声音和字体**：音乐、音效怎么配，中英文用什么字体？（默认只配音效、不配音乐；看板时间线上可以自己拖音乐进去试）
6. **节奏**：发布平台、目标时长、语速？（默认每秒 4.5 字）

用户不在、没法提问时（比如定时任务），全部按默认值生成，并在 `meta.lede` 里写明“按默认值生成：……”。

用户的口播原文不改写。发现事实错误、说法有风险或时长明显超标，写进 `rewrites` 当建议，由用户决定。

## 2. 拆镜头

- 按意群切，单镜 2–9 秒（约 9–40 个字）。长句拆成两镜；同一句话可以在 A-roll 和 B-roll 之间交替。
- **前 5 秒放全片最强的画面**：结果画面或冲击力最大的 B-roll，不留黑场，不寒暄。
- 每个部分开头可以加一张 1–1.5 秒的章节标题卡（`mode: 'T'`，`fixed: 1.4`，`vo` 留空）。
- 选版式（mode）：

| 口播在讲什么 | mode |
|---|---|
| 概念、痛点、对比、情绪 | `E` B-roll 全屏 |
| 软件操作、步骤演示 | `C` 纸面托底录屏（手机录屏用 `ph` 元素） |
| 强调一个数字或一句话 | `AO` 口播 + 叠加贴 |
| 提问、过渡、自我介绍、结尾 | `A` 口播全屏 |
| 真实场景、产品、人物 | `S` 实拍 / 素材 |
| 用视频生成模型出的氛围镜头 | `S`，`rec.dev` 写“AI 视频生成”，提示词放进 `prompts` 并写 `tool`（如 Seedance 2.5） |
| 章节开头 | `T` 标题卡 |

- 没有 A-roll 的视频：从 `modes` 里删掉 `A`、`AO`，全部用 `E`、`C`、`S`。
- 同一种版式不要连续超过 3 镜（连续的操作演示除外）。
- 时长由引擎按字数自动估算，一般不写；标题卡写 `fixed`。用户在时间线上调过的镜头，回改时按第 7 节写 `fixed` / `gap` / `clips`。
- 镜头编号 S01、S02……；回改时拆镜用 S07a、S07b，不重新编号。

## 3. 每个镜头写什么

| 字段 | 必填 | 写什么 |
|---|---|---|
| `id` | 是 | `S01` 起 |
| `ch` | 是 | 所属章节 id |
| `mode` | 是 | 见上表 |
| `vo` | 是 | 这一镜的口播原文，一字不改；标题卡留空 |
| `m` | 是 | 画面预览元素，见第 4 节 |
| `d` | 是 | 给剪辑看的画面排布说明：画面上有什么、怎么动、红圈圈哪里 |
| `tr` | 否 | 和上一镜怎么接 |
| `rec` | 需要录屏、实拍、素材时 | `{ dev, what, steps, p }`。`dev` 如“Mac 录屏”“手机录屏”“实拍”“素材”；`steps` 写具体到点哪里、停几秒；`p` 指向 `prompts` 里的提示词 key |
| `br` | 有 B-roll 或叠加贴时 | `{ id, k: '全屏' 或 '叠加', dur, d }`。全屏编号 BR01 起，叠加贴 OV01 起，标题卡模块统一叫 BR-T；同一个模块再次出现只写 `{ id }` |
| `sfx` | 是 | 音效，按所选风格的音效语言写 |
| `flag` | 否 | 录之前要核实的事 |
| `fixed` | 否 | 这一镜的时长（秒）。标题卡必写；其他镜头只在用户调过时长后写 |
| `gap` | 否 | 和上一镜之间的间隔（秒），负数表示和上一镜重叠。只在用户在时间线上拖出空隙或重叠时写 |
| `clips` | 否 | 各轨道单独的位置：`{ 轨道: [相对本镜开头的偏移秒, 时长秒] }`，轨道是 `a`、`rec`、`br`、`ov`。例如叠加贴晚 0.6 秒出现、只停 2.4 秒：`clips: { ov: [0.6, 2.4] }` |
| `ref` | 否 | 参考与风格：字符串数组，如 `['动效风格参考：neon_style.mp4（霓虹数据风格）', '照着 S01 的配色']`。来自素材画布的连线，或用户直接给的参考 |
| `layers` | 否 | 手动指定时间轴轨道 `['a','rec','br','ov']`，一般不用 |

时间规则：镜头按 `shots` 数组顺序排，每镜的开头 = 上一镜结尾 + `gap`；时长 = `fixed`，没写就按字数估算。每镜的第一条轨道（A/AO 是 `a`，C/S 是 `rec`，E/T 是 `br`）是这一镜的“主 clip”，其他轨道默认和主 clip 对齐，写了 `clips` 就按它偏移。

如果录屏需要先让某个工具（WorkBuddy、豆包、Claude 等）做出特定画面，或者某个镜头要用视频生成模型来出，把要发给它的提示词完整写进 `prompts`，在 `rec.p` 里引用。看板的「提示词」页会把它们按镜头列成清单，可以单条或一次全部复制。这是看板最有用的部分之一：照着提示词就能稳定复现画面。

## 4. 画面预览元素 `m`（手绘分镜）

`m` 是一个数组，每项是 `['元素名', 参数…]`。坐标 x、y、w、h 都是占画面宽、高的百分比（0–100）。字号 `size` 的单位是 u（横屏 4:3 时 1u 约等于画面宽的 1%；其他比例由引擎自动换算）。所有元素都会被画成手绘分镜的样子。

规则：
- 所有元素放在 0–100 以内；底部 12% 留给字幕，不放文字。
- A-roll 镜头的叠加元素放右侧三分之一（x ≥ 58），不要压到人。
- 文字写短。预览是给人看排布的，不是成片。
- 画面元素按从底到顶的顺序写，后写的盖在上面。
- 每个元素属于哪条轨道由引擎自动判断：`pres` 归 V1 口播；`photo`、`scr`、`ph`、`win2` 归 V2 录屏；其余元素在有叠加贴的镜头里归 V4，否则归这一镜唯一的那条轨道。要强制指定，在元素最后加一个对象，如 `['tag', 62, 24, '重点', '', -2, { L: 'ov' }]`。
- 同一个对象还能写出现时间和入场方式：`t` 是相对这条轨道 clip 开头的秒数，`a` 是入场（`pop` 弹出、`fade` 淡入、`up` 从下滑入、`left` / `right` 从左 / 右滑入、`draw` 像手写一样划出、`zoom` 放大推入），如 `['circ', 10, 30, 40, 16, -4, { t: 1.2, a: 'draw' }]`。预演时元素会按时出现并播放入场，生成动效任务时也会写成“第 1.2 秒划出”。口播里说到某个词才出现的东西，按字数估一下秒数写上。
- 有运镜或明显动作的镜头，至少画一个 `cam` 或 `mv`，让人一眼看出镜头怎么走。

| 元素 | 参数 | 用途 |
|---|---|---|
| `pres` | x, y, w, h | A-roll 人像（铅笔小人），通常 `['pres',0,0,100,100]` |
| `photo` | x, y, w, h, 说明, rot | 实拍或素材占位（分镜常用的打叉框 + 文字说明） |
| `scr` | x, y, w, h, 窗口标题, '行1\|行2\|!高亮行', rot | 电脑录屏线稿。行之间用 `\|` 分隔，行首加 `!` 会用红色马克笔高亮 |
| `win2` | x, y, w, h, 标题, '左栏行\|…', '右栏对话\|…' | 左文件右对话的双栏窗口 |
| `ph` | x, y, h, 标题, '行\|行' | 手机录屏线稿，宽度自动按比例算 |
| `card` | x, y, w, h, 文字, rot, 小字 | 纸片卡 |
| `tag` | x, y, 文字, 序号, rot | 深色标签条 |
| `ttl` | x, y, 中文, 英文, size | 大标题（毛笔手写），以 x 为水平中心 |
| `num` | x, y, w, h, 数字, 形状, 标签, rot | 编号卡，形状可选 circle、triangle、square、diamond、hex、ring |
| `bub` | x, y, w, h, 文字 | 对话气泡 |
| `badge` | x, y, 文字 | 红色角标（如 999+） |
| `stamp` | x, y, 文字, rot | 红色印章 |
| `cal` | x, y, w, h, 标题, 红点数, rot | 月历 |
| `grid` | x, y, w, h, 标题, 格数, 圈第几格 | 编号格子（如 14 天） |
| `chip` | x, y, 文字, rot | 小纸签 |
| `stack` | x, y, 文字, rot | 一摞纸 |
| `list` | x, y, w, h, ['项1','项2'], rot | 被红线划掉的清单 |
| `env` | x, y, w, h, rot | 信封 |
| `box` | x, y, w, h, 标签 | 盒子、邮箱 |
| `web` | x, y, w, h, 标签, rot | 网页缩略 |
| `tbl` | x, y, w, h, 标签 | 表格 |
| `plat` | x, y, w, 标签 | 平台横条（下方写标签） |
| `crate` | x, y, w, h | 纸箱 |
| `strip` | y | 横贯画面的地面线 |
| `dia` | x, y, size, 是否戴皇冠 | 黑菱形主角，以 (x, y) 为中心 |
| `bigq` | x, y, 文字, size | 大号强调字符（如红色问号），以 (x, y) 为中心 |
| `txt` | x, y, 文字, size, 'zh' / 'en' / 'hand' | 自由文字（毛笔 / 英文手写 / 硬笔手写） |

| `kbd` | x, y, '⌘\|K' | 快捷键按键 |
| `search` | x, y, w, 文字 | 搜索框 |

常用排布（横屏，直接改文字用）：

```js
// A 口播全屏
[['pres', 0, 0, 100, 100]]
// AO 口播 + 右侧叠加
[['pres', 0, 0, 100, 100], ['tag', 60, 22, '要强调的一句', '', -2], ['stamp', 64, 40, '关键数字', -6]]
// C 电脑录屏 + 红圈
[['scr', 6, 8, 88, 80, '软件 · 页面', '第一步|!要圈的那一步|第三步', -1], ['circ', 6, 26, 40, 14, -4]]
// C 手机录屏在右 + 左侧步骤条
[['ph', 60, 6, 88, 'App 名', '步骤一|步骤二|!关键一步'], ['tag', 6, 20, '长按', '1', -2], ['tag', 6, 36, '选择', '2', 1.5]]
// C 左右对照：电脑 → 手机
[['scr', 4, 10, 52, 66, '电脑', '……', -2], ['arrow', 57, 44, 64, 44], ['ph', 67, 6, 88, '手机', '……']]
// E 标题 + 编号卡 + 慢推
[['ttl', 50, 12, '大标题', 'E N G L I S H', 7], ['num', 6, 40, 19, 36, 1, 'circle', '第一点', -2], ['num', 29, 42, 19, 36, 2, 'triangle', '第二点', 1.5], ['cam', 20, 15, 60, 60, 'push', '慢推']]
// T 章节标题卡
[['strip', 70], ['txt', 6, 7, '01', 6, 'en'], ['ttl', 50, 30, '章节名', 'C H A P T E R', 11], ['dia', 50, 62, 7]]
// S 实拍 + 运动方向
[['photo', 0, 0, 100, 100, '实拍：桌面上的手机特写'], ['mv', 30, 60, 60, 40], ['note', 4, 6, '手从左下入画', 2.4]]
```

竖屏（9:16、3:4）：元素改成上下排列；录屏线稿宽度用 86–92；手机录屏用 `ph` 时 h 取 70–80；标题 size 用 8–12。

## 5. 核实与占位

- 不编造结果。生成耗时、积分、数据、效果这类只有实测才知道的，写成 `【实测后填：说明】`，引擎会高亮。
- 口播里提到的产品功能、入口、限制，能查就查官方文档或可靠报道。查不到、说法冲突、或者口播说法和文档不一致，写进该镜头的 `flag`。
- 涉及隐私（他人头像昵称、孩子正脸、邮箱手机号、账户信息）的录屏，在 `steps` 或 `flag` 里提醒打码。

## 6. 生成 HTML 并交付

模板是技能目录里的 `template.html`（制作看板引擎 v2）。它内嵌了风格库的 70 张截图，有 700 多 KB：**不要把它整份读进来，也不要手抄或改动样式和引擎**。看板只用 `BOARD` 数据生成：

1. 把 `BOARD` 写成一个文件，比如 `board.js`，内容是 `const BOARD = { … };`。想看字段格式，读 `template.html` 开头到 `/* ==== BOARD DATA END ==== */` 为止的那一小段示例就够了。
2. 运行技能目录里的脚本生成看板：`python3 scripts/build_board.py board.js 输出.html "项目名 制作看板"`。脚本只替换 `BOARD DATA START` 到 `BOARD DATA END` 之间的数据和 `<title>`。
3. 回改时先取出现有数据：`python3 scripts/build_board.py --extract 现有看板.html > board.js`，改完再用第 2 步重新生成。

不能运行脚本的环境：复制一份 `template.html`，用编辑工具只替换 `BOARD DATA START` 到 `BOARD DATA END` 之间的内容和 `<title>`，其余部分原样保留。

`BOARD` 顶层字段：

| 字段 | 写什么 |
|---|---|
| `meta` | `key`（项目英文名加日期，用于浏览器本地存储，不同项目不能重复）、`no`（如“制作看板 No.05”）、`project`、`title`（看板大标题）、`latin`、`ar`（如 '16:9'）、`res`（如 '1920×1080'）、`fps`（默认 30，导出 XML 用）、`date`、`version`（从 1 开始）、`cps`（语速）、`presenter`（A-roll 占位文字，如“光郡口播”）、`lede`（两三句说明这份看板怎么看）、`footer` |
| `style` | 成片的配色（写给做动效的人看，也决定预览里红笔的颜色 `accent`）：`bg`、`paper`、`ink`、`bar`、`accent`、`ui`、`line`、`fg`、`noise` |
| `chapters` | `[{ id, name, en }]`，顺序就是视频顺序 |
| `modes` | 本片用到的版式，沿用模板里的定义，按需删减或改描述 |
| `transitions` | `[[从, 到, 怎么接, 音效]]` |
| `prompts` | `{ key: { name, text, tool } }`，录屏前要发给工具的提示词、视频生成提示词；`tool` 写用在哪个工具（如 `Seedance 2.5`、`Claude`） |
| `canvas` | 可选。预先规划好的「风格 → 镜头」连线，第一次打开素材画布时自动摆好：`[{ style: '风格 id', shots: ['S03', 'S04'], note: '补充要求', say: '连线上的说明' }]`。风格 id 用风格库里的（lemo-opuscar 的文件夹名如 `dark-keynote`，或技能名如 `dark-paper-fable-motion`）。用户要求风格多样、或已经说了哪段用什么风格时写上 |
| `shots` | 镜头数组，见第 3 节 |
| `preps` | `[[类别, 要准备什么]]` |
| `rewrites` | `[[镜头, 现在的说法, 建议改成, 原因]]`，没有就留空数组 |
| `specs` | `rec: [[标题, [要点…]]]` 录屏通用设置；`brIntro` 一句话；`br: [[标题, [[项, 内容]…]]]` B-roll 规格（尺寸、帧率、全屏和叠加贴的格式、字体、声音） |
| `styles` | 可选。本片专用风格，会出现在风格库最前面：`[{ id, cn, en, zh, pal: ['#色值'…], skill, url }]`。`skill` 是要加载的技能名，`url` 是风格说明链接。用户给了自己的风格样片或风格说明时写在这里 |
| `changes` | `[{ v, date, items: [...] }]`，初版写 `['初版']` |

风格预设（`style`，描述成片，不影响手绘预览的纸面和墨线）：

- 黑灰纸面（默认）：`{ name: '黑灰纸面', bg: '#2F2E2B', paper: '#E8E1D2', ink: '#0E0E0E', bar: '#161514', accent: '#E0352B', ui: '#F7F5F0', line: '#E8E1D2', fg: '#E8E1D2', noise: true }`
- 米白纸面：`{ name: '米白纸面', bg: '#E7E1D3', paper: '#FBF8F1', ink: '#161514', bar: '#161514', accent: '#D63A2A', ui: '#FFFFFF', line: '#161514', fg: '#161514', noise: true }`
- 深色科技：`{ name: '深色科技', bg: '#0D1117', paper: '#E6EDF3', ink: '#0D1117', bar: '#010409', accent: '#2F81F7', ui: '#FFFFFF', line: '#E6EDF3', fg: '#E6EDF3', noise: false }`
- 用户有自己的风格时，从风格说明里取颜色填进去；有专门的 B-roll 风格 Skill（例如黑灰纸面寓言动效）时，B-roll 清单的写法、音效词汇都按那个 Skill 来，并注意画幅和那个 Skill 的默认画幅是否一致。

看板里用户能做的事（交付时简单告诉用户）：

- **时间线**：拖 clip 中间移动，拖两端改时长；「联动」打开时同一镜头的各轨道一起动（按住 Alt 临时切换）；「波纹」打开时改尾部时长后面的 clip 跟着挪；「磁吸」吸到播放头和其他 clip 的边缘；⌘Z / ⇧⌘Z 撤销重做；「重置时间线」回到初版。
- **音频**：音乐、音效、口播录音直接拖到 A1 口播 VO / A2 音效 / A3 音乐轨（拖到别处会按长度自动分：25 秒以上进音乐轨），或点「导入音频」放在播放头处。音频 clip 可移动、裁剪两端，拖顶部两个白点调淡入淡出，在右侧调音量和入点；轨道头的 M 是静音。音乐默认 60% 音量、淡入 1 秒、淡出 2 秒。
- **预演**：在页面任何地方按空格（正在输入文字时除外）或点「预演」，画面和所有音频轨一起播放，可 1× / 2× / 4×；已到位的视频素材会在预览里跟着时间线播放。
- **画布**：直接拖动元素；右下角蓝色方块改大小；箭头类拖两端的圆点；方向键微调（Shift 加大步长）；Delete 删除；右侧面板改坐标、旋转、文字；下方按钮给当前镜头加文字、纸片卡、标签、红圈、箭头、运动箭头、运镜框、批注。
- **组件库**：预览画面左侧的「▦ 组件库」（收起后预览左边缘会留一个蓝色把手，点它或预览下方的「▦ 组件库」按钮重新打开；素材画布左侧的库同理），按文字、标注、卡片、界面、数据、物件、人物与镜头、组合分类，60 多个手绘组件，可以搜索。拖到预览画面上松手就放在那个位置，点一下放到画面中间；加在当前镜头上，加完可以继续拖、改大小、在右侧面板改文字和数据。组合类（左右对比、三步流程、前后对比等）一次放进多个元素。
- **对比成片**：预览下方的「◧ 对比成片」。导入剪好的整条成片（或者在素材画布里把某一镜的成片拖进镜头框），预览上会盖一层成片，用蒙版擦开和手绘预演对比：「滑杆」拖白线左右对比，「橡皮擦」用鼠标擦出成片，「圆形」从某一点往外拉开；「自动擦过」自动播一遍擦除动画，按空格可以左右同步播放。成片和看板时间对不上时，在「成片偏移」里按镜头调秒数。旁边的 ⛶ 只把预览画面全屏，用来录这类对比画面。适合在介绍视频里做“预演 vs 成片”的段落，也适合拍完回头检查成片有没有跑偏。
- **主题和全屏**：右上角「◐ 跟随系统 / ☀ 浅色 / ☾ 深色」切换看板配色（手绘分镜画面始终是纸面）；「⛶ 全屏」让看板占满屏幕，所在环境不允许网页全屏时按 F11（Mac：⌃⌘F）。页面铺满整个浏览器宽度，大屏上预览、时间线和侧栏都会跟着变大。
- **库（素材画布左侧，「▤ 库」开关）**：「镜头」页按口播 / 录屏 / 实拍 / 素材 / 动效列出全部镜头，已在画布上的标「在画布」：拖到画布上放下，点一下已在画布的镜头会定位过去。「风格」页列出风格库，拖到空白处成为风格节点，直接拖到某个镜头框上会自动连线。选中镜头框按 Delete 是把它从画布上拿走（镜头本身不删）。
- **生成动效任务**：风格节点双击可以写补充要求（比如只借配色、节奏更快）；连到镜头后点节点上的「▶ 生成动效任务」，或工具栏的「▶ 生成全部动效任务」，会弹出一份写好的任务说明：用哪个风格（lemo-opuscar 风格附 STYLE.md 链接和安装命令，自己的风格写明要加载哪个技能）、每个镜头的时间、口播、画面排布、B-roll 说明、音效、分镜元素和连线说明，以及交付要求。可以改几句再复制或下载 .md，发给做动效的 Agent。
- **素材画布**：默认是选择工具（鼠标指针）：点选节点、拖空白处框选、Shift 加选，拖动节点移动（可以多选一起拖）。按住空格（或切到抓手 H、按鼠标中键）拖动平移；滚轮平移，⌘/Ctrl + 滚轮或触控板双指缩放；「看全部」缩放到全貌。
  - 视频和图片从电脑拖进某个框直接到位（框变绿，录屏镜头在「录屏与素材」里自动勾上）；拖到空白处先放着，之后拖进框；从框里把素材拖出来就取消到位。
  - 双击改名：双击镜头框标题给它起备注名，双击素材改显示名（不影响导出时的文件名），双击便签改内容。
  - 连线：悬停节点出现右侧圆点，拖到另一个节点就连上；点线选中，双击线写说明（如“用这个风格”“配色照这个”）；Delete 删除选中的线或素材、便签（镜头框不能删）。
  - 「＋ 便签」加文字便签；「重新排列框」恢复自动排版。音频文件拖到这里会自动放进时间线的音频轨。
- **导出 XML**：生成 FCP 7 XML（xmeml v5），Premiere Pro、DaVinci Resolve、Final Cut Pro（经 XML 转换）都能导入。画面轨里每个 clip 是按“镜头号_类型”命名的离线占位文件（如 `S04_Mac.mp4`、`S01_BR01.mp4`）；素材画布里已到位的镜头会直接用真素材的文件名，导入后在剪辑软件里链接到本机文件即可；音频 clip 带文件名、入点、音量和淡入淡出，导入后链接到本机同名文件；每个镜头还会生成一个带口播文字的标记点。按住 Shift 点「导出 XML」改为复制 XML 文本（下载被浏览器拦住时用）。在 Claude 的网页里打开时，导出会保存成一个装着 XML 的 .zip（Claude 网页只允许保存部分格式），解压后再导入。剪映目前没查到能直接导入 XML，要进剪映得先进达芬奇或 Premiere，或者用第三方工具转换；跟用户说清楚，别说成“直接导入剪映”。

交付方式按所在环境选：

- **Claude**：把 HTML 发布成网页（Artifact），发布时声明 `capabilities: { downloads: true }`，导出 XML 和下载动效任务 .md 才能在网页里保存文件。给出链接。回改时更新同一个文件，链接不变。
- **WorkBuddy**：把 HTML 保存到工作区，用预览或独立文件浏览器打开；要发给剪辑师，就用「分享 → 发布为网站」。
- **豆包**：输出完整的 .html 文件给用户下载，或用支持的网页预览打开。
- 其他环境：输出完整 HTML，提示用户存成 .html 后用浏览器打开。

页面上的评论、勾选、时间线和画布改动存在当前浏览器里，拖进来的音频、视频、图片存在当前浏览器的 IndexedDB 里，换设备、换浏览器不会同步（换了浏览器把同一个文件重新拖进来就行）。时间线和画布改动按看板版本号分开存，AI 回改升版本后会自动从新版本开始；音频位置跨版本保留。

交付前自检：

- 每句口播都在某个镜头里，顺序和原稿一致，没有漏句，没有改字。
- 前 5 秒是强画面。
- 每个 `rec` 都写清了怎么操作；要靠提示词出画面的，提示词已经放进 `prompts`。
- `br` 编号不重复；同一模块复用时只写 `{ id }`。
- 元素坐标都在 0–100 以内，文字不压底部字幕区；有运镜的镜头画了 `cam` 或 `mv`。
- 结果、数字没有编造，用了【实测后填】。
- 能运行代码的环境里，打开一次确认没有报错（可以用 node 逐段 `new Function()` 检查脚本能否解析）。

交付时用三五行告诉用户：总时长、镜头数、几处待核实，以及怎么在时间线上拖音乐、怎么用「复制修改给 AI」回改。

## 7. 按评论和改动回改

用户粘回一段以「【制作看板评论」开头的文字时，里面可能有四部分：整片评论、时间线改动、画布改动、镜头评论，另外还可能列出已到位的素材和时间线上的音频。

1. **时间线改动**：每行是 `镜头号：{"gap":…, "fixed":…, "clips":…}`。把这三个值原样写进对应镜头的同名字段；值是 `null` 就删掉这个字段。如果有「镜头顺序：S01 → S03 → S02 …」，按这个顺序重排 `shots` 数组。顺序变了会让口播顺序和原稿不同，照用户的改动做，但在修改记录里写明，并在回复里提醒一句。
2. **画布改动**：每行是 `镜头号：[...]`，用这个数组整组替换该镜头的 `m`，不要再改动里面的坐标。如果新的画面和 `d`（画面排布说明）对不上，顺手更新 `d`。
3. **素材画布连线**：每行是 `镜头号 ← 参考对象，说明：…`。把参考对象和说明合成一句写进那个镜头的 `ref`（例如 `S01 ← 图片 霓虹参考（文件 neon_style.png），说明：用这个霓虹风格` 写成 `ref: ['风格参考：neon_style.png「霓虹参考」——用这个霓虹风格']`），并在这一镜的 `br.d` 或 `d` 里提一句按参考做。这份列表是画布上当前的全部连线：之前从画布连线来的 `ref`，如果已经不在列表里，就删掉。风格连线写成 `ref: ['动效风格：浮世绘 Ukiyo-e（lemo-opuscar/ukiyoe，https://github.com/lemomo-ai/lemo-opuscar/blob/main/styles/ukiyoe/STYLE.md）——补充要求']`，自己的技能风格写成 `'动效风格：黑灰纸面寓言（技能 dark-paper-fable-motion）'`。两个镜头之间的连线（`A —— B`）表示两镜要统一处理，在两镜的 `ref` 里互相写上。镜头备注名只是用户给框起的名字，可以写进 `d` 帮助理解，不改 `id`。
4. **已到位的素材和音频**：只是告诉你哪些镜头已经拍好（对应的素材文件名）、时间线上放了什么音乐音效。已到位的镜头可以在修改记录里写一句，不用再在 `flag` 里提醒去拍；文件本身留在用户浏览器里。关于音频：可以记进修改记录或 `specs.br` 的声音一项（例如“音乐：xxx.mp3，00:05 淡入”）；音频本身留在用户浏览器里，不用也没法写进 BOARD。
5. **评论**：只改评论点到的镜头；“整片”评论按意思调整全局（节奏、风格、版式比例），并在修改记录里写清影响了哪些镜头。
6. 镜头编号不变；新增的镜头用 a、b 后缀（S07a），删除的在修改记录里写明。
7. `meta.version` 加 1，`changes` 追加一条 `{ v, date, items }`，每条写成“S07：B-roll 改成实拍桌面特写”“S03：时长改为 4.2 秒，叠加贴晚 0.6 秒出现”这样具体的说明。
8. 用 `scripts/build_board.py` 重新生成完整 HTML（Claude 里发布到同一个 Artifact，保持链接不变）。
9. 回复里用几行说改了什么，并提醒用户到「评论与改动」页点「清空全部评论」，避免下次重复提交。时间线和画布的改动已经写进新版本，页面会从新版本重新开始，不用手动清。

评论如果和口播原文冲突（比如要求删一句口播），先确认是不是要改口播，再动手。

## 8. 收到「【动效任务」时

用户粘回一段以「【动效任务」开头的文字时，这是从看板素材画布生成的动效需求，不用改看板，直接按它做动效：

1. 先读任务里指定的风格：lemo-opuscar 的风格先读给出的 STYLE.md 链接（装了 lemo-opuscar 技能就用它）；写着“我自己的动效技能”的，先加载那个技能。
2. 每个镜头按给出的时长、口播、画面排布和分镜元素做。分镜图是手绘示意，只取排布和运动，画风按风格来。
3. 用户自己的动效习惯照旧适用（字体、只配音效不配音乐、前 5 秒要抓人、在 Mac 本地渲染等，以对话和记忆里为准）。
4. 按任务里的交付要求命名和输出；做完提醒用户把成片拖回素材画布对应的镜头框。
